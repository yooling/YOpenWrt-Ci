#---- ★整条无线栈（关掉驱动还不够，界面照样会冒出无线页）----
#现象与根因（2026-10-10 实测于亚瑟 noWiFi 固件）：
#  只关 ath11k 之后，「网络 → 无线」菜单依然存在，点进去列出 radio0 / radio1，
#  状态全是「设备未激活」——一堆点不动的死条目。
#  根因是 DTS 层面 WiFi 设备节点并没有被删除：target 里那个 ipq6018-nowifi.dtsi
#  名叫 nowifi，实际只改了 Q6 预留内存（16MB），它第 3 行就是 #include "ipq6018.dtsi"，
#  WiFi 节点原样保留。于是 /etc/board.json 里仍有 wlan 段，wifi-scripts 照样生成
#  /etc/config/wireless，界面就有了内容。
#  而 LuCI「网络 → 无线」菜单的显示条件恰恰是「/etc/config/wireless 里存在 wifi-device」
#  （luci-mod-network 的菜单定义：depends.uci → wireless @wifi-device）。所以只要把
#  这个配置文件从源头掐掉，菜单自己就消失了，不需要去改 LuCI 的源码。
#关法：wpad-openssl 是整条无线栈的总开关，依赖链是
#      wpad-openssl → hostapd-common → wifi-scripts，
#  而 wifi-scripts 提供的 /sbin/wifi 就是把 /etc/board.json 写成 /etc/config/wireless 的
#  那个程序。关掉 wpad-openssl 一处，hostapd-common 与 wifi-scripts 会一起消失。
#  它来自 target 的 DEFAULT_PACKAGES（target/linux/qualcommax/Makefile），不写 =n 会被默认选中。

CONFIG_PACKAGE_hostapd-common=n
CONFIG_PACKAGE_wifi-scripts=n

#★本清单分三档，改动前先看清楚自己在动哪一档：
#    8.2  =y  日常刚需，直接进固件
#    8.3  =m  冷门或已有替代，只编包不进固件，需要时从 Release 里 apk add

#  冷门插件一律用 =m 而不是删 —— 编出来但没装的那部分会被打进 Packages-extra 包发布，
#  等于「先精简，用着缺了再补」，不用来回重编固件。这套「=m 为主」的写法正是参考

#======================= 8.1 科学上网：nikki + openclash 双栈 =======================
#★2026-10-12 定：亚瑟两份（WiFi / noWiFi）统一「nikki 为主 + openclash 备用」，

#  两个都装了也不能同时开，运行时有两条硬约束（详见 JDCloud-WiFi.txt 第八节顶部）：
